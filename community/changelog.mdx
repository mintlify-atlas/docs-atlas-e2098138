## Release Schedule

Reshaped follows a predictable release schedule:

<Steps>
  <Step title="Patch releases">
    **Weekly to bi-weekly**
    
    Bug fixes and minor improvements
  </Step>
  
  <Step title="Minor releases">
    **Monthly**
    
    New features and enhancements
  </Step>
  
  <Step title="Major releases">
    **Yearly (maximum)**
    
    Breaking changes and major updates
  </Step>
</Steps>

## Contributing to Changelog

All user-facing changes should include a changeset:

```bash
# Create a changeset for your PR
pnpm changeset

# Select the version bump type
# - patch: bug fixes
# - minor: new features
# - major: breaking changes

# Write a clear, user-focused description
```

See the [Contributing Guide](/community/contributing) for detailed instructions.

## Canary Releases

Canary releases are pre-release versions for testing:

```bash
# Install the latest canary
pnpm add reshaped@canary

# Or a specific canary version
pnpm add reshaped@3.10.0-canary.16
```

<Warning>
  Canary releases are unstable and should not be used in production. They may include experimental features or untested changes.
</Warning>

## Reporting Issues

Found a bug? Report it on GitHub:

<Steps>
  <Step title="Check existing issues">
    Search [GitHub issues](https://github.com/reshaped-ui/reshaped/issues) to see if it's already reported.
  </Step>
  
  <Step title="Create a reproduction">
    Use [CodeSandbox](https://codesandbox.io/) or similar to create a minimal reproduction.
  </Step>
  
  <Step title="Open an issue">
    Include:
    - Reshaped version
    - Browser and OS
    - Steps to reproduce
    - Expected vs actual behavior
    - Link to reproduction
  </Step>
</Steps>
